TBIBI BACKEND WIRING PLAN (SPRING)
Version: 1.0
Date: 2026-04-02

Goal
- Implement the backend little by little for the existing frontend without rewriting UI.
- Keep frontend IDs/structure stable; replace static/demo data with API responses.

Current Frontend Reality (important)
- Frontend pages already exist and currently run with static/mock data.
- Dashboard doctor cards and doctor profile text are static.
- Medical record iframe/history are static.
- Nearby services search currently runs in browser demo mode.
- Signup is frontend validation only; patient optional medical file upload UI exists.
- Emergency numbers are hardcoded in modal.
- Login still has demo redirect behavior.

IMPORTANT CONSTRAINTS
- Do NOT force frontend redesign while wiring backend.
- Replace static data endpoint by endpoint.
- Keep contracts simple JSON first, then harden validation/security.

==================================================
PHASE 0 - PROJECT BASELINE (SPRING BOOT)
==================================================
1) Confirm stack
- Spring Boot 3.x
- Spring Web
- Spring Validation
- Spring Data JPA
- MySQL (already in pom runtime)
- Optional later: Spring Security + JWT

2) Configure environments
- application.properties profiles:
  - dev (local)
  - prod (future)
- Add DB URL, username, password for local MySQL.
- Enable SQL migration tool (recommended Flyway or Liquibase).

3) CORS for frontend
- Allow frontend origin (the host you serve html from).
- Methods: GET, POST, PUT, PATCH, DELETE.

Deliverable
- Backend runs cleanly with DB connection and basic /api/health endpoint.

- id

- specialty

5) medical_files

Deliverable

==================================================
PHASE 2 - AUTH + ACCOUNT ENDPOINTS
==================================================
1) POST /api/auth/register
Request
{
  "firstName": "...",
  "lastName": "...",
  "email": "...",
  "phone": "+216...",
  "password": "...",
  "role": "PATIENT|DOCTOR",
  "subscriptionCode": "BASIC|PREMIUM"
}
Response
- 201 created user summary

2) POST /api/auth/login
Request
{
  "email": "...",
  "password": "..."
}
Response
- if security implemented: JWT + profile summary
- else temporary session token

3) GET /api/account/me
- Return user profile + active subscription.

4) PUT /api/account/me
- Update profile fields (firstName, lastName, phone, address if added).

5) PUT /api/account/password
- Update password with currentPassword/newPassword.

Deliverable
- Frontend login/signup can switch from demo redirects to real API calls.

==================================================
PHASE 3 - SIGNUP FILE UPLOADS
==================================================
Required because frontend already supports:
- Doctor verification docs (required for doctor role)
- Patient medical files (optional for patient role)

Endpoints
1) POST /api/uploads/doctor-docs (multipart/form-data)
Fields
- doctorId (or infer from auth)
- idCard (file)
- diploma (file)
- license (file)

2) POST /api/uploads/patient-medical-files (multipart/form-data)
Fields
- patientId (or infer from auth)
- files[] (multiple)

Storage choice
- Start local file storage (dev): /uploads/...
- Keep abstraction so later move to S3/Cloud/Azure Blob.

Validation
- accepted content types: pdf/jpg/jpeg/png (+ dcm if desired)
- max size per file
- antivirus scan (optional later)

Deliverable
- Signup process can upload files and persist metadata in DB.

    "status": "ONLINE|OFFLINE",
    "experience": "11 Ans Expérience",

]

2) GET /api/doctors/{id}
- Return detailed profile for right summary panel.

3) GET /api/patients/me/medical-files
- Return file history list for middle panel.

4) GET /api/patients/me/medical-files/{fileId}/download
- Return file stream for iframe/display.

Deliverable
- Remove hardcoded doctor names/photos/descriptions and static file history.

PHASE 5 - NEARBY MEDICAL SERVICES
==================================================
Current frontend uses direct Overpass call in browser.
Move to backend endpoint:

GET /api/nearby-medical?lat=...&lng=...&radius=3000
Response
[
  {
    "name": "...",
    "type": "Pharmacie|Hôpital|Clinique|Cabinet médical",
    "distance": 450,
    "street": "...",
    "city": "..."
  }
]

Implementation
- Backend can proxy Overpass API first.
- Add timeout/retry and simple cache (recommended 2-5 min).

Deliverable
- Frontend no longer depends on browser direct external call.

SECURITY + QUALITY CHECKLIST (RUN IN PARALLEL)
==================================================
- Hash passwords with BCrypt.
- Never store plaintext passwords.
- Validate all request DTOs.
- Add global exception handler (consistent error JSON).
- Add API pagination when listing bigger datasets.
- Add audit fields (createdAt/updatedAt).
- Add role checks (doctor/patient/admin).
- Add integration tests for critical endpoints.

Standard error response format
{
  "timestamp": "...",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "path": "/api/..."
}
